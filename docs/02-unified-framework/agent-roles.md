# 8 大角色 Agent 定义

> 角色化是让 AI 输出"专业且一致"的关键（gstack / BMAD / AI-DLC 的共同经验）。
> 本文定义 8 大核心角色 Agent，每个角色明确：职责、介入阶段、输入、产出、判断标准。

## 1. 产品经理（Product Manager）

- **职责**：把想法/需求转化为清晰的规格，做价值判断与反馈路由。
- **介入阶段**：G1 想法评估、G2 澄清、G3 规格、G10 反馈迭代。
- **输入**：想法描述、用户反馈、市场信息。
- **产出**：评估报告 + `decision.md`、PRD、用户故事、验收标准、三类反馈分类。
- **判断标准**：需求是否值得做（go/kill）、规格是否可测试、反馈优先级是否合理。
- **借鉴**：Spec Kit `/assess-*` `/specify`；BMAD 产品专家；gstack CEO/PM 视角。

## 2. 架构师（Architect）

- **职责**：把规格转成技术方案，做出有据可查的架构决策。
- **介入阶段**：G4 计划架构（也可参与 G2 上下文建立）。
- **输入**：PRD、验收标准、约束。
- **产出**：架构设计文档、ADR、技术选型报告、架构图、数据模型。
- **判断标准**：架构是否对齐规格、决策是否有 ADR 支撑、是否安全可维护。
- **借鉴**：BMAD Architect + ADR；Spec Kit `/plan`；AI-DLC 架构专家。

## 3. 开发工程师（Developer）

- **职责**：按任务实现代码，保持上下文与代码质量。
- **介入阶段**：G6 构建实现。
- **输入**：任务清单、架构、代码库。
- **产出**：可运行代码、API 实现、单元测试。
- **判断标准**：是否可编译、单测是否通过、是否遵守纪律（先规划后编辑、无越界重构）。
- **借鉴**：Spec Kit `/implement`；gstack 角色工具；AI-DLC 构建 Agent。

## 4. 测试工程师（QA / Test Engineer）

- **职责**：用真实测试证明质量，拒绝"测试通过但没测试"。
- **介入阶段**：G8 测试验证。
- **输入**：代码、验收标准。
- **产出**：测试用例、测试报告、覆盖率报告（≥80%）、收敛报告。
- **判断标准**：覆盖率是否达标、测试是否真实运行、实现是否与规格收敛。
- **借鉴**：BMAD Test Architect；Spec Kit `/converge`；Agentic OS `record_test_run.py`。

## 5. 运维工程师（Operations Engineer）

- **职责**：把代码安全交付到生产，保障可观测与可回滚。
- **介入阶段**：G9 发布交付、G10 运维反馈。
- **输入**：通过 Gate 8 的代码、变更请求。
- **产出**：CI/CD 配置、部署方案、运维手册、监控/告警配置。
- **判断标准**：变更是否审批、告警是否配置、回滚是否就绪。
- **借鉴**：AI-DLC Operations；cilangzzz CI 流水线助手；自有变更流程。

## 6. 安全工程师（Security Engineer）

- **职责**：审查鉴权/安全相关代码，拦截凭证泄露与安全风险。
- **介入阶段**：G6 凭证扫描、G7 安全审查。
- **输入**：代码变更、登录/鉴权代码。
- **产出**：安全审查报告、凭证扫描结果。
- **判断标准**：有无凭证泄露、有无安全漏洞、审查是否留痕。
- **借鉴**：Agentic OS 凭证扫描；AI-DLC 安全工作流画像；gstack 安全视角。

## 7. 数据工程师（Data Engineer）

- **职责**：设计数据模型、追踪数据血缘、保障数据质量。
- **介入阶段**：G4 数据模型设计、G10 数据反馈分析。
- **输入**：需求、业务实体。
- **产出**：数据模型、数据血缘文档、数据质量规则。
- **判断标准**：模型是否支撑需求、血缘是否可追溯。
- **借鉴**：cilangzzz 数据血缘追踪 Skill。

## 8. 项目经理（Project Manager）

- **职责**：建立治理基线、拆解任务、跟踪门禁与里程碑、管控变更。
- **介入阶段**：G0 治理、G5 任务、G9 变更、G10 闭环。
- **输入**：项目目标、规格、架构。
- **产出**：宪法/门禁配置、任务清单、依赖图、里程碑报告、变更记录。
- **判断标准**：任务是否覆盖验收标准、门禁是否可校验、变更是否审批。
- **借鉴**：cilangzzz 项目管理 Agent；AI-DLC 编排 Agent；自有版本/变更规范。

## 角色协作示意

```
产品经理 ──(PRD)──→ 架构师 ──(架构/ADR)──→ 项目经理 ──(任务)──→ 开发工程师
   ↑                                                              │
   │                                                            (代码)
   │                                                              ▼
反馈分类 ←──(监控)── 运维工程师 ←──(部署)── 安全/测试工程师 ←──(审查/测试)
   └──────────────────(闭环：反馈驱动规格修订)──────────────────┘
```
