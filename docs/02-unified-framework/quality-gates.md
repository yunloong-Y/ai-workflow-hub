# 质量门禁 Gate 0–10 与检查清单

> 门禁（Gate）是工作流中"不达标不放行"的质量检查点。借鉴 AI-DLC 的人工审批门、Spec Kit 的清单、cilangzzz 的 Gate 1-5、以及自有体系的"覆盖率 < 80% 不通过"。

[返回首页](../../README.md) · [English](./quality-gates.en.md) · [统一工作流](./unified-workflow.md)

---

## 门禁设计原则

1. **可量化**：每条门禁都有明确判据（覆盖率 ≥80%、报告 = Converged 等）。
2. **可追溯**：门禁结论与证据留痕，来源绑定（source-bound）。
3. **能强制就强制**：能用 git hook / CI 自动拦截的，不依赖 Agent 自觉（Agentic OS 教训）。
4. **按规模裁剪**：轻量路径只过核心门禁（G6/G8/G9），完整路径过全部。

## 门禁总表

| Gate | 所属阶段 | 判据（放行标准） | 强制方式 | 失败处理 |
|---|---|---|---|---|
| **G0** | 治理基线 | 宪法/角色/门禁/工具链齐备且可校验 | 人工 + 配置校验 | 补齐治理要素 |
| **G1** | 想法评估 | 结论 = `go` 且证据充分 | 人工审批 | `kill` 或 `needs-clarification` 回补 |
| **G2** | 澄清启动 | 关键歧义已消解，上下文充分 | 人工审批 | 回到澄清 |
| **G3** | 规格需求 | 规格完整、可测试、ID 全链路可追溯 | 清单 + ID 校验 | 补规格/补 ID 映射 |
| **G4** | 计划架构 | 架构对齐规格、ADR 有据、安全评审通过 | 人工 + ADR 检查 | 修订架构 |
| **G5** | 任务拆解 | 任务覆盖全部验收标准、依赖清晰 | 覆盖度检查 | 补任务 |
| **G6** | 构建实现 | 可编译、单测通过、无凭证泄露 | `scan_credentials.py` + 编译 | 修复/回滚 |
| **G7** | 代码审查 | 无阻塞问题、审查有据可查 | 人工 + 审查记录 | 修复后复审 |
| **G8** | 测试验证 | 覆盖率 ≥80%、测试真实运行、Converged | CI + 指纹校验 | 补测/修复 |
| **G9** | 发布交付 | 变更审批通过、监控告警与回滚就绪 | `validate.sh` + 审批 | 阻断发布 |
| **G10** | 反馈迭代 | 反馈已分类入待办、知识库已更新 | 人工 + 状态检查 | 补录反馈 |

## 关键门禁详细说明

### Gate 3 · 规格门禁

- [ ] 每条需求有唯一 ID
- [ ] 每条需求有可测试的验收标准（Gherkin 优先）
- [ ] 需求 → 任务 → 代码 → 测试 → 发布 的 ID 流向箭头完整
- [ ] 规格与项目宪法无冲突

### Gate 6 · 构建门禁（机器强制）

- [ ] `scan_credentials.py` 凭证扫描通过（可接 pre-commit hook）
- [ ] 代码可编译/可构建
- [ ] 单元测试通过
- [ ] 无未被要求的重构

### Gate 8 · 测试门禁（机器强制）

- [ ] 测试覆盖率 ≥80%
- [ ] 测试由 `record_test_run.py` 真实运行并记录退出码
- [ ] 代码指纹与测试运行匹配（测试后代码未变更）
- [ ] `converge` 报告为 `Converged`
- [ ] CI 跑的是真实测试套件

### Gate 9 · 发布门禁（机器强制）

- [ ] 变更经在线表单 + AI 评估
- [ ] 变更审批通过（人审批）
- [ ] `validate.sh` 通过（阶段与证据完整）
- [ ] 告警规则已配置
- [ ] 回滚方案就绪

## 异常处理与升级机制（自有体系）

| 异常类型 | 触发条件 | 处理路径 |
|---|---|---|
| 门禁超时 | 48 小时未处理 | 自动升级到上一级负责人 |
| 人工介入 | 门禁判定需要人工判断 | 转入人工队列并记录 |
| 门禁失败 | 覆盖率/证据不达标 | 阻断放行，回退到对应阶段修正 |
| 变更紧急 | 线上紧急修复 | 走紧急通道，事后补审批与记录 |

> **超时升级：48 小时未处理自动升级** 是自有体系"异常处理机制"的核心规则。

---

## 告警分级（自有体系）

| 级别 | 场景 | 响应 |
|---|---|---|
| P0 严重 | 发布失败、门禁被绕过、凭证泄露 | 立即响应，阻断 + 通知负责人 |
| P1 高 | 门禁超时、测试失败 | 4 小时内响应 |
| P2 中 | 覆盖率下降、反馈积压 | 24 小时内响应 |
| P3 低 | 文档未更新、知识库待补 | 常规迭代处理 |

## 监控健康度指标（自有体系）

健康度仪表板应展示：门禁通过率、平均门禁处理时长、超时升级次数、测试覆盖率趋势、缺陷逃逸率、反馈闭环率、知识库更新频率。
